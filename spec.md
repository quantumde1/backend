# Спецификация маркетплейса

## 1. Назначение системы

Система предназначена для выставления товаров на продажу продавцам и возможности покупателям оформлять заказы в удобное им место выдачи.

## 2. Роли пользователей

- **Покупатель** — зарегистрированный пользователь, который может просматривать товары, добавлять их в заказ и оформлять заказы.
- **Продавец** — зарегистрированный пользователь, который может добавлять и редактировать свои товары, просматривать заказы на свои товары.
- **Администратор** — пользователь с расширенными правами: может просматривать все заказы и товары, управлять статусами заказов, блокировать пользователей.

## 3. Пользовательские сценарии

### 3.1. Регистрация

**Кратное описание**: Пользователь может зарегистрироваться.

**Сценарий**:

1. Пользователь открывает страницу регистрации.
2. Вводит email, пароль, имя, фамилию, выбирает роль (покупатель / продавец).
3. Отправляет форму.
4. Система создаёт запись `User` с ролью, выполняет авторизацию.
5. Пользователь перенаправляется на главную страницу.

### 3.2. Создание товара продавцом

**Краткое описание**: Продавец может создать карточку нового товара.

**Сценарий**:

1. Продавец открывает страницу «Мои товары».
2. Нажимает кнопку «Добавить товар».
3. Заполняет поля: название, описание, цена, количество.
4. Отправляет форму.
5. Система создаёт запись `Product`.
6. Товар отображается в списке «Мои товары» и в общем каталоге

### 3.3. Оформление заказа покупателем

**Краткое описание**: Покупатель может оформить заказ.

**Сценарий**:

1. Покупатель открывает каталог товаров.
2. Выбирает один или несколько товаров, указывает количество для каждого.
3. Переходит в оформление заказа.
4. Видит список выбранных товаров, количество, цену за единицу и общую сумму.
5. Подтверждает оформление заказа.
6. Система: 
	- проверяет, что для каждого товара `quantity` ≥ запрошенному количеству; 
	- уменьшает `quantity` у всех задействованных товаров; 
	- создаёт запись `Order` со статусом `new`; 
	- создаёт записи `OrderItem` для каждого товара; -
	- вычисляет и сохраняет `total_amount`.
7. Покупатель видит страницу «Заказ оформлен» с номером заказа и составом.

## 4. Функциональные требования

### Регистрация и авторизация

#### FR-AUTH-01

Система должна позволять гостю зарегистрировать учётную запись по имени, email и паролю.

#### FR-AUTH-02

Система должна проверять уникальность email при регистрации.

#### FR-AUTH-03

Система должна позволять пользователю авторизоваться по email и паролю.

#### FR-AUTH-04

Система должна различать роли: покупатель, продавец и администратор

#### FR-AUTH-05

Система должна запрещать доступ к функциям продавца и администратора пользователям без соответствующей роли.

#### FR-AUTH-06

Система должна позволять пользователю выйти из учётной записи.


### Товары и поиск

#### FR-PROD-01

Система должна отображать список доступных товаров.

#### FR-PROD-02

Система должна отображать карточку доступного товара.

#### FR-PROD-03

Система должна поддерживать фильтрацию по диапазону цены.

#### FR-PROD-04

Система должна поддерживать поиск товаров по названию.

#### FR-PROD-05

Система не должна показывать пользователям недоступные товары.


### Управление товарами со стороны продавца

#### FR-SELL-01

Система должна позволять продавцу создавать, редактировать и удалять карточки его товаров.

#### FR-SELL-02

Система должна предоставлять продавцу статистику по продажам его товаров.

#### FR-SELL-03

Система должна запрещать редактирование товаров, которые не принадлежат текущему продавцу.


### Оформление заказов

#### FR-ORDER-01

Система должна позволять покупателю добавлять доступные товары в корзину.

#### FR-ORDER-02

Система должна позволять покупателю просматривать корзину.

#### FR-ORDER-03

Система должна позволять покупателю оформлять заказ, на основе его корзины.

#### FR-ORDER-04

Система должна позволять покупателю выбирать пункт выдачи.

#### FR-ORDER-05

Система должна позволять покупателю оплачивать заказ с помощью системы MIR.

#### FR-ORDER-06

После успешной оплаты статус заказа должен измениться на `PAID`, При неуспешной оплате статус заказа должен измениться на `PAYMENT_FAILED`.


## 5. Нефункциональные требования

### Производительность

#### NFR-PERF-01

Оформление заказа должно завершаться не более чем за 3 секунды без учёта внешнего платёжного провайдера.

#### NFR-PERF-02

Система должна поддерживать постраничный вывод каталога товаров.

#### NFR-PERF-03

Система должна обрабатывать 10000 запросов в секунду.
